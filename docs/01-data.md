# 第 1 章：平行语料与数据清洗

对应代码：`nmt/corpus.py`

## 平行语料是什么

**平行语料就是两种语言一句一句对齐的文本**：第 i 行英文配第 i 行德文，模型从"这句英文对应的德文长这样"里学会翻译。

三种容易混淆的东西：

| 类型 | 长什么样 | 用途 |
| --- | --- | --- |
| 平行语料 | 英德一一对应的句对 | 监督训练、评测（本项目用的） |
| 单语语料 | 只有一种语言的文本 | 预训练、回译（back-translation） |
| 可比语料 | 两种语言讲同一件事，但没做句级对齐 | 检索、弱监督（挖一挖也能得到平行句对） |

## 本项目用哪两份数据

| 语料 | 规模 | 域 | 用途 |
| --- | --- | --- | --- |
| News-Commentary v16（de-en） | 294,498 句对 | 新闻评论 | 训练集 |
| WMT-News v2019（de-en） | 45,913 句对 | 新闻 | newstest2013 做验证，newstest2014/2017/2018/2019 做测试 |

两份都来自 [OPUS](https://opus.nlpl.eu/)（把互联网上公开平行语料聚合起来的门户），直接给 URL 就能下，不需要注册。

### 为什么不自己切测试集

BLEU 只在**同一份测试集 + 同一套切词方式**下才有可比性。WMT 的 `newstest2014`
是《Attention Is All You Need》报 27.3 BLEU 用的那份，也是后来几乎所有 NMT 论文的标配。
你自己的模型跑出的数字可以直接和它们摆在一起看。自己随手切一个测试集，分数再高也不知道算高还是低。

### 关于 newstest2014 的句数

OPUS 整理的这份是 **3003 句**。你可能会看到某些论文写"newstest2014 有 2737 句"——
那是当年过滤掉空行和重复段之后的版本。两者的 BLEU 会有零点几的差异，
所以**和自己做消融实验横向比是可靠的，和论文比只能看量级**。

## 真实数据有多脏

`python -m nmt.corpus` 会打印一份清洗报告，格式是这样：

```
输入 294498 句，保留 xxxxxx 句（xx.x%）
    丢掉   xxxxx 句：<具体原因>
    ...
```

本项目在清洗管线里依次检查这些情况（`CleanConfig` 里的阈值可以调）：

| 检查 | 抓什么 | 为什么必须做 |
| --- | --- | --- |
| 空行 | 段落之间补的空行 | 会让模型学会"什么都不输出" |
| U+FFFD | 非法 UTF-8 留下的替换字符 `�` | 说明这行本来就是坏的 |
| 汉字 / 日文 | 英德语料里不该出现的字符 | 几乎只有一种可能：抓取串行或编码坏了 |
| 拉丁字母比例 | 一侧大部分不是拉丁字母 | 筛掉混进来的俄语、希腊语内容 |
| **功能词判语言** | "德文那一列其实是英文" | 见下方详述 |
| 长度比例 | 德文/英文字符数比值超出 0.5~2.5 | 文档级对齐的错位（一句英文对着一整段德文） |
| 完全重复 | 同一句对被收录多次 | 新闻语料里很常见 |

### 为什么"功能词判语言"是个必要的土办法

英语和德语都用拉丁字母，光看字符集根本分不出谁是谁。但真实语料里确实存在
"德语那一列其实是英语"的对齐错位，这种样本对训练是纯粹的毒药。

本项目的做法是准备两张高频功能词表：

```
英语：the that of to in is was were for with on as by at from ...
德语：der die das und ist sind nicht mit sich auf für von den dem ein ...
```

然后**只在证据明确时才丢**：句子至少 6 个词，一侧全是对方的标记词、自己一个都没有。
为什么要加"至少 6 个词"这个条件？因为新闻标题经常一个功能词都没有
（`New Questions Over California Water Project`），不能因为缺少证据就误杀。

正式项目会用 fastText 之类的语言识别模型，这里用土办法是为了**只用标准库**，
而且你能一眼看懂它的判断依据。

### 文档级对齐的语料不能直接当句子对用

News-Commentary 是论文指定的标准训练数据之一，但它的对齐质量远不如人工标注的测试集。
所以你会看到训练 loss 一路降、验证 BLEU 却不高 —— 一部分原因就是训练数据本身的噪声。
在真实的机器翻译工程里，数据清洗往往比换模型结构更能涨点。

## 自己动手

```bash
# 1. 看清洗报告：每一类丢了多少句
python -m nmt.corpus

# 2. 把长度比例限制收紧（比如 0.7~1.6），看训练集还剩多少
#    改 nmt/corpus.py 里 CleanConfig.min_length_ratio / max_length_ratio

# 3. 加一份不同领域的语料，观察 BLEU 怎么变
#    （域外数据通常是"训练 loss 更低、测试 BLEU 反而掉"）
python -m nmt.corpus --extra europarl     # 欧洲议会辩论，正式书面
python -m nmt.corpus --extra ted2013      # 演讲口语，句子短
python -m nmt.corpus --extra multiun      # 联合国文件，术语密集

# 4. 打开 data/ready/train.src.en 和 train.ref.de，用眼睛扫 100 句
#    人工检查能发现规则漏掉的问题
```

## 报告里应该写什么

改数据之后不要只看"训练集变大了"，值得记录的是：

* 保留率、各类脏数据的占比；
* 训练集/验证集的平均长度与 95 分位长度（决定 `max_tokens` 设多大）；
* dev BLEU 和 test2014 BLEU 都报 —— 两者差很多，说明过拟合验证集，或者两个集合分布不同。
