# 第 1 章：平行语料与数据清洗

对应代码：`nmt/corpus.py`

## 平行语料是什么

**平行语料就是两种语言一句一句对齐的文本**：第 i 行英文配第 i 行中文，模型从"这句英文对应的中文长这样"里学会翻译。

三种容易混淆的东西：

| 类型 | 长什么样 | 用途 |
| --- | --- | --- |
| 平行语料 | 中英一一对应的句对 | 监督训练、评测（本项目用的） |
| 单语语料 | 只有一种语言的文本 | 预训练、回译（back-translation） |
| 可比语料 | 两种语言讲同一件事，但没做句级对齐 | 检索、弱监督（挖一挖也能得到平行句对） |

## 本项目用哪两份数据

| 语料 | 规模 | 域 | 用途 |
| --- | --- | --- | --- |
| News-Commentary v16 | 12.6 万句对 | 新闻评论 | 训练集 |
| WMT-News v2019 | 约 2 万句对 | 新闻 | newsdev2017 做验证，newstest2017/2018/2019 做测试 |

两份都来自 [OPUS](https://opus.nlpl.eu/)（把互联网上公开平行语料聚合起来的门户），直接给 URL 就能下，不需要注册。

**为什么测试集必须是官方的？**

因为 BLEU 只在同一份测试集上才有可比性。WMT 的 `newstest2019` 是当年比赛的官方测试集，多数论文报的分数都在它上面算。你用自己切的测试集得到 45 分、别人在官方测试集上得到 25 分，两个数字放一起毫无意义。

## 真实数据有多脏

`python -m nmt.corpus` 会打印一份清洗报告，本项目在 News-Commentary 上的实际结果：

```
输入 125996 句，保留 98234 句（78.0%）
    丢掉   14300 句：单侧超过 400 字符
    丢掉    9768 句：空行
    丢掉    2715 句：编码坏行（含替换字符 U+FFFD）
    丢掉     602 句：中英长度比例失衡（疑似对齐错位）
    丢掉     376 句：中文侧汉字比例过低（可能语言放错）
    丢掉       1 句：英文侧拉丁字母比例过低
```

逐条解释：

* **空行**：moses 格式里段落之间有空行，两侧都是空字符串。这类样本会让模型学会"什么都不输出"。
* **编码坏行**：原始文件不是合法 UTF-8，用 `errors="replace"` 读进来会留下 U+FFFD（`�`）。看到这个字符直接扔。
* **长度比例失衡**：News-Commentary 的中文侧从中文新闻网站抓取，做的是**文档级对齐**。结果就是"一句英文对着一大段中文"这种错位。中英字符数之比一般在 0.3~0.8，超出 0.2~2.5 的大概率是错的。
* **语言放错**：中文那一列其实是英文（原网站有些稿子本身就是英文）。

真实项目里还可以加：去重、语言识别（fastText）、标点规范化、HTML 标签清理、按 token 而不是按字符过滤长度。本项目做了最关键的几项，剩下的留给你扩展。

## 一个坑：文档级对齐的语料不能直接当句子对用

News-Commentary 是论文指定的标准训练数据之一，但对齐质量远不如人工标注的测试集。所以你会看到训练 loss 一路降、验证 BLEU 却不高 —— 一部分原因就是训练数据本身的噪声。在真实机器翻译工程里，数据清洗往往比换模型结构更能涨点。

## 自己动手

```bash
# 1. 换更严格的长度比例限制，看训练集还剩多少
#    改 nmt/corpus.py 里 CleanConfig.min_length_ratio / max_length_ratio
python -m nmt.corpus

# 2. 加一份不同领域的语料，观察 BLEU 怎么变
#    （域外数据通常是"训练 loss 更低、测试 BLEU 反而掉"）
python -m nmt.corpus --extra un
python -m nmt.corpus --extra ted2013

# 3. 打开 data/ready/train.src.en 和 train.ref.zh，用眼睛扫 100 句
#    人工检查能发现规则漏掉的问题
```

## 报告里应该写什么

改数据之后不要只看"训练集变大了"，值得记录的是：

* 保留率、各类脏数据的占比；
* 训练集/验证集的平均长度与 95 分位长度（决定 `max_tokens` 设多大）；
* dev BLEU 和 test BLEU 都报 —— 两者差很多，说明过拟合验证集，或者两个集合分布不同。
